# Inahosai Server

[日本語](README.md) | [English](README_en.md)

小規模な HTTP サーバーで、日本の学校文化祭ホームページを動かします。

**茎崎中学校 稲穂祭**（テーマ **つなぐ**）のために書かれました。コードは MIT です。学校名、コピー、写真、PDF は MIT ではありません。フォークは、Java、HTML、CSS、JavaScript の中を文字列検索するのではなく、1 つの YAML ファイルを編集するだけで別の学校になれるべきです。

Deploy example: [https://inahosai.serbekun.com/](https://inahosai.serbekun.com/)

> **学校の PDF、しおり、生徒の写真をコミットしないでください。**
> それらはほぼ必ず未成年者の個人情報を含みます。
> `data/`（gitignore 済み）に置いてください。そうしないと GitHub 上と JAR 内に入ってしまいます。

## 日本語

中学校・高等学校の文化祭ホームページを動かすサーバーです。茎崎中学校の稲穂祭向けに書きましたが、**設定ファイルを書き換えれば他校でも使えます。** Java / HTML / CSS / JS を触らずに済むようにしてあります。

オープンソースにした理由は単純です。文化祭サイトを「作って」と頼まれた他のプログラマが、ゼロから書き直さずにこのコードを土台にできるように。好きなだけ変えてください。

### 先に読むこと

1. **デフォルト設定は茎崎・稲穂祭のままです。** 自分の学校用に直さない限り、サーバーは起動を拒否します（`is_setup_readed_and_config_edited`）。他人の学校名で公開しないための仕組みです。
2. **しおり・作品集・生徒が写った写真を GitHub に push しないでください。** 未成年の個人情報です。`data/` は gitignore 済みです。本物のファイルはそこに置き、リポジトリと JAR には入れないでください。
3. 詳しい設定は [`SETUP.md`](SETUP.md) です。

### 起動（短い版）

Java 21 が必要です。

```sh
cp src/main/resources/config.default.yaml config.yaml
# config.yaml を自分の学校向けに編集し、
# is_setup_readed_and_config_edited: true にする
./gradlew run
```

http://127.0.0.1:2323/ で開きます。初回起動時、同梱テンプレートは `data/static/` に展開されます。

## これは何か

1 つの文化祭のためのセルフホスト型ホームページです。

| ルート | 役割 |
| --- | --- |
| `/` | ホーム — テーマ、コンセプト、グラフ |
| `/jikan` | 時間 — 時間割 / 過去・現在・未来 |
| `/manabi` | 学び — 展示作品 |
| `/basho` | 場所 — 会場 / ライブ |
| `/sedai` | 世代 — 「世代をつなぐ」ページ |
| `/works/{key}` | 複数 PDF がある作品のファイル選択ページ（ナビには出ない） |

静的ファイル（CSS、JS、画像、PDF）は `/static/v0/` 以下で配信されます。ページは YAML から埋められる Mustache テンプレートで、**プロセス起動時に一度だけレンダリング**され、その後は ETag 付きのバイト列として配信されます。

スタック: Java 21、Javalin 6、jmustache、Jackson YAML。それ以外のフレームワークはありません。現在のバージョン: `pre-alpha-2026-09-11`。

このリリースは設定駆動型のサイトです。ユーザーログインも、思い出掲示板も、**インストールすべきデータベースもありません**。それらは後で来ます。それらの保存先の選択はすでに決まっています（[思想](#哲学)を参照）。

## なぜオープンソースなのか

毎年、学校の誰かが「文化祭のウェブサイトを作って」と、動かない締め切りの中で頼まれます。その仕事のほとんどは独自ではありません。いくつかのページ、プログラム PDF、ライブ配信の埋め込み、校舎の写真、名前と日付。

このリポジトリは、その人がフォークし、設定を変え、自分のファイルを入れ、公開できるように存在します。好きなように変えてください。**コード**の MIT ライセンスは、そのための許可です。

それは、茎崎、稲穂祭、スローガン、写真、誰かのしおりを再利用する許可では*ありません*。それらは学校と、写真に写っている人々のものです。

## 哲学

### コードではなく設定

`config.yaml` が学校です。名前、日付、スローガン、コンセプト行、ページ一覧、グラフの単語と位置、配信 ID、作品タイトル、フッターリンク — すべて。

それがこのファイルの目的です。フォークは、別の文化祭になるために Java、HTML、CSS、JavaScript を編集する必要があるべきではありません。テンプレート内の学校名を変えようとしているなら、代わりに設定に入れてください。

同梱のデフォルトは茎崎 / 稲穂祭のための動作するサイトです。それはこのサーバーが書かれた学校だからです。それらのデフォルトを別の学校のドメインで配信するのは静かな誤りなので、サーバーは次を設定するまで**起動を拒否**します。

```yaml
is_setup_readed_and_config_edited: true
```

実際にファイルを読んだ後に。タイポは起動エラーであり、空の値ではありません。未知のキーは名前で拒否されます。未設定の任意キーはその要素を隠します（死んだ `href="#"` や 404 アイコンは出ません）。不足する*必須*キー（`school.name_ja`、`festival.name`、`festival.start_date`）はプロセスを起動させますが、すべてのページに `SETUP.md` を指すバナーが表示されます。

和暦文字列（`令和8年`）は暦年ではなく `festival.start_date` から計算されます。元号は年途中で変わります。

このファイルに秘密情報を入れてはいけません。トークンと接続文字列は環境変数（`INAHOSAI_ADMIN_TOKEN`、および後でデータベース URL）に置きます。

### なぜページはサーバーで一度だけレンダリングされるのか

ブラウザではなく、リクエストごとでもありません。

- 文化祭の URL は LINE で共有されます。LINE のクローラーは JavaScript を実行しません。`<title>` と `og:` タグはすでに HTML 内にある必要があります。そうでなければチャットカードは空です。
- ヒーローキャンバスは最初のフレームで `data-text` をラスタライズします。学校名が後から `fetch` で届くと、看板は組み立てられ、震え、再構築されます。
- 5 ページはミリ秒でレンダリングされます。リクエストごとに行うと、負荷時に失敗する可能性を買うだけで、何も得ません。
- JavaScript をオフにしても、サイトにはレイアウト、コピー、ナビゲーションが残ります。消えるのはパーティクル効果だけです。
- Mustache はデフォルトでエスケープします。DOM を `innerHTML` で埋めることは、設定値が XSS になる方法です。

設定を必要とするスクリプト（テーマグラフ）は、すでにページ内にある JSON アイランドを読みます — 追加の往復はありません。CSS と JS は長いキャッシュを持つ本物の静的ファイルのままです。

設定を変更 → 再起動、または `INAHOSAI_ADMIN_TOKEN` が設定されている場合は `POST /api/v0/admin/reload`。

### なぜ PostgreSQL なのか（そしてなぜこのリリースに含まれないのか）

この pre-alpha は、プロセスクラッシュで失われるものを保存しません: YAML、テンプレート、画像、PDF。データベースは遊んでいる重りになるだけです。

訪問者入力を受け付ける次の機能（思い出掲示板、アイデア投稿、ゲストが入力したものすべて）は **PostgreSQL** を使います。「RAM に置いて数分ごとに JSON ファイルにフラッシュする」ではありません。これは設計上の選択であり、性能上の選択ではありません。

文化祭は 2 日間で数百から数千の訪問者です。HashMap 対 Postgres は携帯電話のレイテンシの前では見えません。見えないわけではないもの:

- **クラッシュはデータ損失です。** 定期的な JSON フラッシュには窓が残ります。30 人が思い出を書いた後、最後のフラッシュが 5 分前でプロセスが死ぬと、それらのメッセージは消え、投稿者は家に帰っています。年に一度のイベントでは受け入れられません。
- **同時書き込み。** 1 つの JSON ファイルの read-modify-write は、それを破損させる古典的な方法です。
- **モデレーションはクエリです**（「保留中」、「この IP の過去 1 時間」、「ソフト削除」）。全ファイルスキャンではありません。
- **フォーク。** 次の学校は茎崎より大きい可能性が高いです。後でスタックの最下層でストレージを切り替えると、データを失います。ユーザーデータが存在する瞬間から PostgreSQL であれば、フォークはおもちゃの店を継承しません。

SQLite は単一の学校（1 ファイル、デーモンなし）には十分でしょう。Postgres がデフォルトなのは、このプロジェクトがフォークされることを意図しているからです。後には高校によっても。アクセスパターンはどちらにせよ `Repository` インターフェースの背後に置かれます。

その層が存在するまで、**ゲスト入力用の JSON ストアを発明しないでください。** 待つか、機能をオフのままにしてください。

### サードパーティリクエストはゼロ

現在、サイトは CDN、Web フォント、解析と通信しません。ファビコンはインライン data URI です。学校サイトの訪問者は子どもです。彼らのブラウザは、ページを表示するためだけに第三者に電話をかけるべきではありません。ライブページの YouTube 埋め込みは唯一の例外で、配信 ID が設定されている場合のみです。そのままにしてください。

## 学校の文書をコミットしないでください

これはフォークが実際の害を引き起こす最も簡単な方法です。

しおり、地図、作品カタログ、クラス写真には、**未成年者の名前、顔、その他の個人データ**が日常的に含まれます。それらを git に入れると公開されます: リポジトリ、すべてのフォーク、すべてのクローン、GitHub Release の JAR、そしてファイルを「削除」した後の git 履歴。

| 置き場所 | GitHub に出る? | 用途 |
| --- | --- | --- |
| `data/static/pdf/` | いいえ（`data/` は gitignore 済み） | 本物のしおり、本物の作品 PDF |
| `data/static/images/` | いいえ | 本物の校舎写真、本物の展示写真 |
| `src/main/resources/pdf/` | **はい、しかも JAR 内** | プレースホルダー `sample.pdf` のみ |
| `src/main/resources/images/` | **はい、しかも JAR 内** | プレースホルダーのみ |

初回起動時、サーバーは同梱テンプレートを `data/static/` にコピーし、すでにディスク上にあるファイルは上書きしません。その後は JAR ではなくディスクを読みます。したがって:

1. 一度実行します。
2. `data/static/pdf/sample.pdf` と `data/static/images/school.png` を自分のファイルに置き換えます。
3. それらの置き換えファイルを `src/main/resources/` にコピーし直さないでください。
4. `git push` の前に `git status` を実行し、`.pdf` / 生徒の写真がないか確認します。

任意のゲート: `pdf.require_auth: true` と空でない `pdf.token` は、すべての PDF を学びページのパスワードフォームの後ろに置きます。訪問者が一度トークンを送信すると、サーバーは HttpOnly cookie を設定し、以降の PDF リクエストはそれで認証します。トークンは URL、アクセスログ、`Referer` に現れません。それは実行中サーバー上のアクセス制御です。コミットしたファイルを**保護しません**。

識別可能な生徒の写真は肖像権です。許可は学校の問題であり、ソフトウェアライセンスの問題ではありません。許可がないなら、その写真を公開しないでください — git にもサイトにも。

## クイックスタート

```sh
git clone https://github.com/serbekun/inahosai_server.git
cd inahosai_server
cp src/main/resources/config.default.yaml config.yaml
```

`config.yaml` を編集します。最低限:

- `school.name_ja`、`festival.name`、`festival.start_date` — 必須。そうでなければすべてのページにセットアップバナーが表示されます
- 日付、スローガン、コンセプト、作品、配信、`site.base_url`（LINE の `og:` タグ、canonical、`/sitemap.xml` に必要）
- `site.repo_url` — *自分の*フォークを指します
- `is_setup_readed_and_config_edited: true` — そうでなければプロセスは終了します

次に:

```sh
./gradlew run                          # production: /setup is not registered
INAHOSAI_ENV=dev ./gradlew run         # development: /setup is a checklist
```

開きます [http://127.0.0.1:2323/](http://127.0.0.1:2323/)。

Release JAR から:

```sh
java -jar inahosai_server-pre-alpha-2026-09-11-all.jar
```

ソースから:

```sh
./gradlew shadowJar
java -jar build/libs/inahosai_server-pre-alpha-2026-09-11-all.jar
```

設定の読み込み順（起動時にログ出力）:

1. `-Dinahosai.config=...`
2. `$INAHOSAI_CONFIG`
3. `./config.yaml`
4. 同梱の `config.default.yaml`

`INAHOSAI_ENV=dev` は `GET /setup` を登録します（キー名と設定済み/未設定のみ — 値は決して表示しません）。`INAHOSAI_ADMIN_TOKEN` は `POST /api/v0/admin/reload` を登録します。

完全なキー一覧、グラフ座標、配信 ID、PDF トークン: **[`SETUP.md`](SETUP.md)**。

## フォークが実際に触るレイアウト

```
config.yaml                 # 自分のもの。git には入れない。config.default.yaml からコピー
data/static/                # 初回起動時に作成。gitignore 済み
  css/ js/ html/            # 展開されたテンプレート。ここでの編集はアップグレード後も残る
  images/                   # 自分の写真
  pdf/                      # 自分のしおり
src/main/resources/         # 上流のプレースホルダーのみ
  config.default.yaml
  html/ css/ js/ images/ pdf/
```

アップグレードは、そのバージョンで*新しい*ファイルだけを展開します。すでにディスク上にあるファイルはそのまま残されます。
